# 문자 발송기 설치 (학원 데스크 PC)

이 문서는 **학원 데스크 PC를 문자 발송기로 만드는 절차**다. 사람이 읽어도 되고, 그 PC의 에이전트가 읽고 실행해도 된다.

에이전트가 이 문서로 작업한다면 **아래 규칙을 먼저 지켜라.**

- **2단계(발신번호)에서 승인된 번호가 없으면 멈추고 사람에게 알려라.** 그 뒤 단계를 다 해도 문자는 나가지 않는다.
- **7단계 전까지는 실제 문자가 나가지 않는다.** 7단계는 건당 요금이 나가는 지점이다 — 사람 확인 없이 켜지 마라.
- **비밀 값(알리고 API 키, 발송기 비밀)을 로그·채팅·커밋 어디에도 남기지 마라.** `.env` 파일에만 둔다.
- 각 단계 끝의 **확인**을 통과하지 못하면 다음으로 넘어가지 마라.

---

## 왜 이런 구조인가

알리고는 **등록된 IP에서 온 요청만** 받는다. 배포된 웹앱(Vercel)은 요청마다 나가는 IP가 달라 거기서는 문자를 보낼 수 없다. 브라우저에서 직접 부르면 IP는 풀리지만 API 키가 화면 소스에 실려 안 된다.

그래서 나눴다.

```
직원이 발송 누름
   └─> 웹앱: 보낼 문자를 DB 큐에 적기만 함
                         ↑
        데스크 PC 가 주기적으로 가져감 (기본 30초)
                         └─> 알리고 호출  ← 학원 회선 IP 로 나감
```

- 알리고 키는 **이 PC 에만** 있다.
- 큐에 쌓이므로 **PC 가 꺼져 있어도 문자가 사라지지 않는다.** 켜지면 순서대로 나간다.
- 실패하면 사유가 남고 3회까지 재시도한다.

---

## 준비물

- 알리고 콘솔 로그인 (아이디 `k740724`)
- 데스크 PC 관리자 권한 (설치·작업 스케줄러)
- Vercel `studycube.cloud` 프로젝트 접근 권한

## 1. 이 PC 의 IP 를 알리고에 등록

```
1. 이 PC 에서 https://api.ipify.org 를 연다 → 나오는 숫자가 학원 회선의 공인 IP
2. 알리고 콘솔 → API 설정 → 그 IP 를 등록
```

**확인** — 등록 후 공유기를 껐다 켜고 `api.ipify.org` 를 다시 열어 **같은 주소인지** 본다.

- 같다 → 사실상 고정. 그대로 진행.
- 다르다 → **유동 IP.** 바뀔 때마다 알리고에 다시 등록해야 한다. 자주 바뀌면 월 오천 원짜리 국내 VPS 로 발송기를 옮기는 편이 낫다(스크립트는 그대로 쓴다).

이 결과를 **기록해 두라.** 9단계(선택)의 판단 근거가 된다.

---

## 2. 발신번호 확인  ← 여기서 막히면 멈춘다

알리고 콘솔 → 발신번호 관리에서 **승인된 번호**가 있는지 본다.

없으면 지금 등록한다. 통신서류 제출과 승인이 필요해 **즉시 되지 않는다.**

**확인** — 승인된 번호가 하나 이상 있다. 없으면 **여기서 멈추고 사람에게 알린다.**

## 3. Node 설치

`https://nodejs.org` 에서 LTS 를 받아 설치한다.

**확인**

```bat
node --version
```

`v20` 이상이면 된다.

---

## 4. 웹앱과 나눠 가질 비밀 만들기

웹앱과 발송기가 서로를 확인하는 값이다. 이 PC 에서 만들고 같은 값을 Vercel 에도 넣는다.

```bat
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```

나온 값을 Vercel 에 넣는다.

```
Vercel → studycube.cloud → Settings → Environment Variables
  이름  SMS_WORKER_SECRET
  값    (방금 나온 값)
  환경  Production
```

> **저장만 하면 적용되지 않는다.** Deployments 에서 최신 배포를 **Redeploy** 해야 새 환경변수가 실린다.

**확인** — 재배포가 끝난 뒤:

```bat
curl -s -o NUL -w "%%{http_code}" -X POST https://www.studycube.cloud/api/sms-worker
```

`401` 이면 정상이다(비밀 없이는 안 열린다는 뜻).

---

## 5. 발송기 파일과 설정 놓기

`C:\studycube-sms\` 폴더를 만들고, 저장소의 **`scripts/sms-worker.mjs` 파일 하나**를 그 안에 복사한다. 다른 파일은 필요 없다 — 이 스크립트는 Node 기본 기능만 쓴다(외부 패키지 없음).

같은 폴더에 `.env` 파일을 만든다.

```
STUDYCUBE_API_BASE=https://www.studycube.cloud
SMS_WORKER_SECRET=(4단계에서 만든 값)
ALIGO_USER_ID=k740724
ALIGO_API_KEY=(알리고 콘솔에서 복사)
ALIGO_SENDER=(2단계 발신번호, 하이픈 없이 숫자만)
```

> **`www` 를 빼면 안 된다.** `studycube.cloud` 는 `www` 로 넘기는 주소라, 빼면 POST 요청이 리다이렉트에서 끊긴다.

**확인** — `.env` 에 값이 비어 있는 줄이 없다.

---

## 6. 시험 실행 (실제 발송 안 됨)

```bat
cd C:\studycube-sms
node --env-file=.env sms-worker.mjs
```

이렇게 뜨면 정상이다.

```
[sms-worker] 시작 (테스트모드, base=https://www.studycube.cloud, 수신 포트=8787, 확인주기=30초)
```

창을 켜 둔 채로, 다른 기기에서 `studycube.cloud` 에 `cto` 로 로그인 → **문자 발송함** → **테스트 발송 추가**.

**확인** — 30초 안에 발송기 창에 줄이 뜬다.

| 출력 | 뜻 |
|---|---|
| `발송 완료` | 배선이 전부 맞다. 시험 모드라 실제 문자는 안 나갔다. |
| `-101 인증오류입니다.-IP` | 1단계 IP 등록이 안 됐거나 IP 가 바뀌었다. |
| `401` | 4단계 비밀이 다르거나, Vercel 재배포를 안 했다. |
| 아무 줄도 안 뜸 | `STUDYCUBE_API_BASE` 의 `www` 를 확인하라. |

---

## 7. 실제 발송 켜기  ← 여기서부터 요금이 나간다

`.env` 맨 아래에 한 줄을 더하고 **발송기를 껐다 켠다**(파일만 고치면 반영되지 않는다).

```
ALIGO_SEND_LIVE=true
```

다시 **테스트 발송 추가** 를 누르되, **받는 번호를 본인 휴대폰**으로 넣는다.

**확인** — 실제로 문자가 온다.

> 사이트의 자동 발송 네 가지(입실·퇴실·이용기간 만료 임박·만료)는 **전부 꺼진 상태로 배포**돼 있다. 여기까지 확인한 뒤 **문자 발송함 → 템플릿 탭**에서 하나씩 켠다. 문구도 거기서 고친다.

## 8. 컴퓨터를 켤 때 저절로 실행되게

`C:\studycube-sms\start-sms.bat` 을 만든다.

```bat
cd /d C:\studycube-sms
node --env-file=.env sms-worker.mjs
```

작업 스케줄러 설정:

```
1. 시작 메뉴 → 작업 스케줄러 → 오른쪽 "작업 만들기" (기본 작업 아님)
2. 일반   — 이름: 스터디큐브 문자 발송기
           "사용자의 로그온 여부에 관계없이 실행" 체크
3. 트리거 — 새로 만들기 → "시작할 때"
4. 동작   — 새로 만들기 → 프로그램 시작 → C:\studycube-sms\start-sms.bat
5. 조건   — "컴퓨터를 AC 전원으로 사용하는 경우에만 실행" 체크 해제
6. 설정   — "작업이 실패하는 경우 다시 시작 간격" 1분, 3회
```

**확인** — PC 를 재부팅한 뒤 작업 스케줄러에서 상태가 **실행 중**이고, 사이트에서 테스트 발송을 넣으면 30초 안에 처리된다.

## 9. (선택) 즉시 발송 — 테일스케일 Funnel

8단계까지면 **최대 30초** 지연으로 문자가 나간다. 학부모 입장에서 입실 알림이 30초 늦는 건 대개 문제가 아니다. **즉시**가 필요하면 이 단계를 한다.

지금은 발송기가 스스로 물어보기만 한다. 웹앱이 발송기를 **직접 부르게** 하면 지연이 사라진다. 다만 이 PC 는 공유기 안에 있어 밖에서 못 닿는다. 공유기에 포트를 여는 방법도 있지만 두 가지가 걸린다 — 학원 네트워크에 구멍이 생기고, 비밀이 평문으로 오간다. 그리고 **유동 IP 라면 IP 가 바뀔 때마다 Vercel 주소도 고치고 재배포해야 한다.**

테일스케일 Funnel 은 이 셋을 다 푼다. **주소가 회선 IP 와 무관하게 고정**이라 Vercel 은 한 번 설정하면 손대지 않아도 된다.

```
1. https://tailscale.com 가입 → 이 PC 에 설치·로그인
2. 관리 콘솔에서 HTTPS 인증서와 Funnel 을 이 tailnet 에 허용
3. 이 PC 에서:
     tailscale funnel --bg 8787
   출력에 나오는 https://<이름>.ts.net 주소를 적어 둔다
4. Vercel → studycube.cloud → Settings → Environment Variables
     이름  SMS_WORKER_URL
     값    https://<이름>.ts.net
     환경  Production
   → 저장 후 Redeploy
5. .env 에 확인 주기를 늘린다(찌르기가 주 경로가 되므로):
     SMS_POLL_SECONDS=300
   발송기 재시작
```

**확인** — 사이트에서 테스트 발송을 넣으면 **몇 초 안에** 발송기 창에 뜬다(30초를 기다리지 않는다).

> 이 단계는 **8단계가 확인된 뒤에** 한다. 둘을 한꺼번에 세팅하면 안 될 때 어디가 문제인지 가려낼 수 없다.

## 안 될 때

| 증상 | 원인과 조치 |
|---|---|
| `-101 … -IP` | 알리고 등록 IP 와 현재 IP 가 다르다. `api.ipify.org` 로 확인 후 재등록. |
| `401` 이 계속 | Vercel 의 `SMS_WORKER_SECRET` 과 `.env` 값이 다르거나, **재배포를 안 했다.** |
| 발신번호 오류 | `ALIGO_SENDER` 는 알리고에 **승인된 번호**여야 하고 하이픈 없이 숫자만. |
| 큐에 쌓이는데 안 나감 | 발송기가 꺼져 있다. 켜면 쌓인 것부터 순서대로 나간다. |
| 시험 문자가 안 옴 | `ALIGO_SEND_LIVE=true` 를 넣고 **발송기를 껐다 켰는지** 확인. |
| 잔액 부족 | 충전 후 문자 발송함 **실패** 탭에서 **다시 보내기**. |
| 문자가 늦게 옴 | `SMS_POLL_SECONDS` 를 확인. 9단계를 안 했다면 최대 그 초만큼 늦는 게 정상이다. |

### 환경변수 정리

| 변수 | 어디에 | 필수 | 설명 |
|---|---|---|---|
| `SMS_WORKER_SECRET` | 양쪽 | 예 | 웹앱과 발송기가 나눠 갖는 비밀. 같아야 한다. |
| `STUDYCUBE_API_BASE` | 발송기 | 예 | `https://www.studycube.cloud` — `www` 필수. |
| `ALIGO_USER_ID` | 발송기 | 예 | `k740724` |
| `ALIGO_API_KEY` | 발송기 | 예 | 알리고 콘솔에서. |
| `ALIGO_SENDER` | 발송기 | 예 | 승인된 발신번호, 숫자만. |
| `ALIGO_SEND_LIVE` | 발송기 | 아니오 | `true` 일 때만 실제 발송. 없으면 시험 모드. |
| `SMS_POLL_SECONDS` | 발송기 | 아니오 | 스스로 확인하는 주기(초). 기본 30. |
| `SMS_WORKER_PORT` | 발송기 | 아니오 | 찌르기 수신 포트. 기본 8787. |
| `SMS_WORKER_URL` | 웹앱 | 아니오 | 9단계에서만. 비우면 찌르지 않고 발송기가 스스로 확인한다. |
